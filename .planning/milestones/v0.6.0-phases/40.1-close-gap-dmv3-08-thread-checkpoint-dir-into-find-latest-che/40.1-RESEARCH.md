### Pattern 1: PhiFlow 3.4.0 moving-obstacle boundary (D-08)
**What:** `Obstacle(geometry, velocity=(vx,vy,vz))` creates a moving obstacle; `make_incompressible` → `apply_boundary_conditions` sets the fluid velocity inside the mask to the obstacle velocity (moving-wall boundary).
**When to use:** TWO_WAY coupling only. ONE_WAY uses `Obstacle(merged)` (stationary, velocity=0 → interior zeroed).
**Example:**
```python
# Source: /opt/homebrew/lib/python3.14/site-packages/phi/physics/fluid.py:27,212-240 [VERIFIED: installed source]
from phi.flow import Obstacle, fluid, Solve

# ONE_WAY (stationary, current behavior):
obstacles_arg = [Obstacle(merged)]  # velocity=0 default, is_stationary=True

# TWO_WAY (moving, NEW):
v_obs = (0.1, 0.2, 0.0)  # per-obstacle velocity integrated from prior force
obstacles_arg = [Obstacle(merged, velocity=v_obs)]  # is_moving=True

velocity, pressure = fluid.make_incompressible(
    velocity, obstacles_arg, solve=Solve(rel_tol=1e-4, abs_tol=1e-4, max_iterations=500)
)
# apply_boundary_conditions (fluid.py:239) does:
#   velocity = (1 - obs_mask) * velocity + obs_mask * (angular + obstacle.velocity)
# Interior cells take the obstacle velocity -> moving-wall BC -> added-mass feedback
```

### Pattern 2: Substep loop (D-06)
**What:** Wrap advect + make_incompressible + force-compute in `for _ in range(coupling_substeps): sub_dt = dt / coupling_substeps`.
**When to use:** Both ONE_WAY and TWO_WAY on the 3D obstacle path. Smaller `sub_dt` → smaller CFL → MORE stable, so ONE_WAY `test_one_way_stable_n100` (finiteness-only) should still pass.
**Example:**
```python
# Source: D-06 + PhiFlow standard advect+project pattern [VERIFIED: codebase + PhiFlow docs]
sub_dt = dt / self.config.coupling_substeps
for _ in range(self.config.coupling_substeps):
    self._velocity = advect.mac_cormack(self._velocity, self._velocity, sub_dt)
    obstacles_arg = self._build_obstacles_arg()  # TWO_WAY adds velocity
    self._velocity, self._pressure = fluid.make_incompressible(
        self._velocity, obstacles_arg, solve=Solve(...)
    )
    forces = self._compute_forces()  # 3D branch
    if self.config.coupling_mode == FluidCouplingMode.TWO_WAY:
        self._integrate_obstacle_velocity(forces, sub_dt)  # v_obs += (F/m)*sub_dt
    self._sim_time += sub_dt
```

### Focus Area 1: PhiFlow 3.4.0 TWO_WAY obstacle-velocity boundary (D-08) — VERIFIED

**Source:** `/opt/homebrew/lib/python3.14/site-packages/phi/physics/fluid.py:21-240` [VERIFIED: installed source + empirical probe]

`make_incompressible` calls `apply_boundary_conditions(velocity, obstacles)` at `fluid.py:137`, which branches on `obstacle.is_stationary`:
```python
# fluid.py:227-240 [VERIFIED]
for obstacle in obstacles:
    obs_mask = resample(obstacle.geometry, velocity, soft=True, balance=1)
    if obstacle.is_stationary:                          # ONE_WAY (velocity=0)
        velocity = field.safe_mul(1 - obs_mask, velocity)              # zeros inside mask
    else:                                               # TWO_WAY (velocity != 0)
        velocity = field.safe_mul(1 - obs_mask, velocity) + field.safe_mul(obs_mask, angular_velocity + obstacle.velocity)
        # ^^ interior cells take obstacle.velocity -> moving-wall BC
```

**Empirical confirmation** (run in this session, `PYTHONPATH=src python3 -c ...`):
- `Obstacle(cyl)` → `is_stationary=True, is_moving=False`; after solve, interior y-velocity = 0.0.
- `Obstacle(cyl, velocity=(0.1, 0.2, 0.0))` → `is_stationary=False, is_moving=True`; after solve, interior y-velocity = 0.2 (= obstacle velocity).
- Both solves produce finite pressure.

**Recommended `step()` implementation shape (D-08, Claude's discretion):**
```python
# In FluidSimulator.__init__: add per-obstacle velocity state
self._obstacle_velocities: dict[str, np.ndarray] = {}  # name -> (vx,vy,vz), init zeros
# In add_instrument: self._obstacle_velocities[name] = np.zeros(3)

# In step(), build obstacles_arg per mode:
def _build_obstacles_arg(self) -> list:
    from phi.flow import Obstacle, union
    geoms = [o.geometry for o in self._obstacles]
    merged = union(*geoms)
    if self.config.coupling_mode == FluidCouplingMode.TWO_WAY:
        # TWO_WAY: feed integrated obstacle velocity back (D-08)
        # Sum per-obstacle velocities into a single merged-obstacle velocity
        # (simplest: use the first/only obstacle's velocity; for multi-obstacle,
        #  a merged velocity is an approximation — acceptable per D-08 discretion).
        v = self._obstacle_velocities[self._obstacle_names[0]]
        return [Obstacle(merged, velocity=(float(v[0]), float(v[1]), float(v[2])))]
    return [Obstacle(merged)]  # ONE_WAY: stationary

# In step(), after force computation (TWO_WAY only):
def _integrate_obstacle_velocity(self, forces: dict, sub_dt: float) -> None:
    # Added-mass: v_obs += (F / m_obs) * sub_dt. m_obs is a small constant
    # (thin instrument -> large acceleration -> instability, RESEARCH Pitfall 8).
    m_obs = 1e-3  # kg, small mass -> thin-instrument instability
    for name, f in forces.items():
        self._obstacle_velocities[name] = self._obstacle_velocities[name] + (f / m_obs) * sub_dt
```

**Structural test mechanism (D-07a):** The cleanest observable is `obstacle.is_moving` on the Obstacle passed to `make_incompressible`. Two approaches:
- **Spy approach (recommended):** monkeypatch `fluid.make_incompressible` (or the FluidSimulator's `_build_obstacles_arg`) to capture the obstacles arg, then assert `obstacles_arg[0].is_moving == True` for TWO_WAY and `is_stationary == True` for ONE_WAY.
- **Interior-velocity approach:** run one `step()` with TWO_WAY and a nonzero obstacle velocity, sample post-solve velocity inside the mask, assert it equals the obstacle velocity (not zero). This is the empirical probe above.

The spy approach is cheaper (no full solve) and more direct. Example:

The loop runs for BOTH modes. Smaller `sub_dt` reduces CFL number → MORE stable, so ONE_WAY `test_one_way_stable_n100` (finiteness-only) is not at risk. The current single-solve `step()` (`fluid_simulator.py:213-259`) becomes the loop body:

```python
# fluid_simulator.py step() restructure [VERIFIED: D-06 + PhiFlow advect/project pattern]
def step(self, dt: float | None = None) -> dict[str, np.ndarray]:
    from phi.flow import Obstacle, Solve, advect, fluid, union
    if dt is None:
        dt = self.config.substep_dt
    sub_dt = dt / self.config.coupling_substeps
    forces: dict[str, np.ndarray] = {}
    for _ in range(self.config.coupling_substeps):
        self._velocity = advect.mac_cormack(self._velocity, self._velocity, sub_dt)
        obstacles_arg = self._build_obstacles_arg()  # D-08: TWO_WAY adds velocity
        try:
            self._velocity, self._pressure = fluid.make_incompressible(
                self._velocity, obstacles_arg,
                solve=Solve(rel_tol=1e-4, abs_tol=1e-4, max_iterations=500),
            )
        except Exception as exc:
            logger.warning("Pressure solve failed: %s", exc)
            self._pressure = None
        if self._pressure is not None and self._obstacles:
            if self.config.dim_3d:
                from surg_rl.fluids.force_computation import _compute_obstacle_forces_3d
                forces = _compute_obstacle_forces_3d(
                    self._velocity, self._pressure, self._obstacles,
                    self._obstacle_names, self.config,
                )
            else:
                # 2D branch BYTE-IDENTICAL to v0.5.0 (SC#1) — single solve, NOT substepped
                from surg_rl.fluids.force_computation import compute_obstacle_forces
                forces = compute_obstacle_forces(
                    self._velocity, self._pressure, self._obstacle_names, self.config,
                )
                break  # 2D path: one solve, exit the loop (preserve SC#1 byte-identical)
        if self.config.coupling_mode == FluidCouplingMode.TWO_WAY and self.config.dim_3d:
            self._integrate_obstacle_velocity(forces, sub_dt)
        self._sim_time += sub_dt
    return forces
```

**Important:** The 2D branch must NOT be substepped (SC#1 byte-identical). The planner should decide the cleanest structure: either (a) substep only the 3D path with an early-return for 2D, or (b) loop with a `break` after the 2D single solve. Both preserve 2D byte-identical. The landmine is: do NOT run 4 sub-solves on the 2D path (changes 2D timing → breaks SC#1).

**ONE_WAY stability note:** 4 sub-solves at `sub_dt = dt/4` halves the CFL number per solve. Advect + project is monotone-stable for CFL ≤ 1; halving it cannot introduce divergence. `test_one_way_stable_n100` asserts only `np.isfinite` per step — this holds a fortiori under substepping. [ASSUMED — the planner should run the test to confirm; if it breaks, raise per D-06, do not skip the loop.]

```python
def test_3d_force_y_axis_physical_magnitude(self):
    """CR-01 regression: a linear y-ramp produces fy = -∇p · V_mask in Newtons.

    Hand-computed: p[i,j,k]=j/16 on 0.3m/16-cell -> grad_y = 1/0.3 Pa/m exactly
    (np.gradient on a linear ramp is exact). V_mask = N_mask * cell_vol.
    fy = -(1/0.3) * V_mask. Asserts within 1% (D-04 tolerance); in practice
    matches to machine precision (rel err 0.0). The unclamped |fy| ≈ 0.0084 N
    is 6 orders below the 1e4 per-axis clamp, so the clamp does NOT mask the
    assertion (the trap that let CR-01's ~53x unit error slip).
    """
    from phi.flow import Obstacle
    from phi.geom import infinite_cylinder
    from surg_rl.fluids.force_computation import _compute_obstacle_forces_3d

    cfg = _make_3d_config()  # 0.3m, 16^3, ONE_WAY
    arr = np.zeros((16, 16, 16), dtype=np.float64)
    for j in range(16):
        arr[:, j, :] = float(j) / 16.0
    p = _make_synthetic_3d_pressure(arr)
    cyl = infinite_cylinder(x=0.15, y=0.15, radius=0.05, inf_dim="z")
    obstacle = Obstacle(cyl)

    forces = _compute_obstacle_forces_3d(None, p, [obstacle], ["cyl"], cfg)
    fy = float(forces["cyl"][1])

    # Hand-computed expected value
    dy = 0.3 / 16
    cell_vol = dy ** 3
    mask_np = field.sample(obstacle.geometry, p).numpy("x,y,z")
    V_mask = float(mask_np.sum()) * cell_vol
    expected_fy = -(1.0 / 0.3) * V_mask  # grad_y = 1/0.3 for p=j/16 on 0.3m domain

    assert abs(fy - expected_fy) / abs(expected_fy) < 0.01, (
        f"fy={fy} vs expected={expected_fy} (rel err > 1% — CR-01 unit regression)"
    )
```

The `1%` tolerance is per D-04; the actual match is exact (`rel err 0.0`). A future change re-breaking the units (re-omitting `dy` from `np.gradient`) would produce `fy ≈ -0.0084 * 0.01875 = -1.58e-4` (off by `dy`), a ~53× error → the 1% tolerance catches it.

```python
def _find_latest_checkpoint(
    task: str, obs_type: str, checkpoint_dir: str | None = None

    """Find latest *.ckpt for task/obs_type, honoring a custom checkpoint_dir.
```
