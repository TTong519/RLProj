- Implemented real TWO_WAY obstacle-velocity feedback in FluidSimulator.step: Obstacle(merged, velocity=(vx,vy,vz)) triggers the moving-wall boundary branch in PhiFlow's apply_boundary_conditions (fluid.py:239), diverging from ONE_WAY's stationary Obstacle(merged). ## Decisions Made

- **m_obs = 1e-3 kg** for the added-mass feedback (D-08 discretion, RESEARCH A2). Small mass → large acceleration → thin-instrument instability. The structural test (D-07a) does NOT depend on m_obs — it observes the branch, not the divergence.
- **2D early-return structure** for SC#1 preservation: the 2D path runs the exact single-solve sequence (advect → stationary Obstacle(merged) → make_incompressible → compute_obstacle_forces → _sim_time += dt) and returns before the 3D substep loop. This is cleaner than a loop-with-break and guarantees the 2D path is untouched.
- **Single-obstacle velocity for TWO_WAY merged Obstacle**: _build_obstacles_arg uses the first obstacle's velocity (self._obstacle_velocities[self._obstacle_names[0]]). For the single-instrument case (every current test), this is the instrument's velocity. Multi-obstacle merged velocity is an approximation (D-08 discretion — "provided TWO_WAY diverges from ONE_WAY on thin instruments").

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Structural test seeds nonzero initial velocity**
- **Found during:** Task 1 (test_two_way_takes_feedback_branch)
- **Issue:** The plan asserts `captured obstacles[0].is_moving is True`, but with the default zero initial velocity, no forces develop (advect of zero velocity is zero, make_incompressible of zero velocity with a stationary obstacle produces zero pressure, forces are zero, obstacle velocity stays zero). PhiFlow 3.4.0 `Obstacle(geom, velocity=(0.0, 0.0, 0.0))` is `is_stationary=True, is_moving=False` (verified empirically). So the assertion would NEVER pass even after GREEN — the fluid stays at rest and the feedback branch cannot be observed.
- **Fix:** Seeded `fs._velocity` with a nonzero StaggeredGrid(0.1, ...) before calling step(), so the pressure solve develops nonzero forces, the TWO_WAY feedback loop integrates them into the obstacle velocity, and `is_moving=True` on the 2nd+ substep. The spy captures the last substep's obstacles (is_moving=True). In RED, the old single-solve code captures Obstacle(merged) (no velocity kwarg, is_moving=False) — clean RED. In GREEN, the substep loop produces is_moving=True on later substeps — clean GREEN.
- **Files modified:** tests/test_fluids/test_3d_coupling.py (test_two_way_takes_feedback_branch)

## Issues Encountered

- Discovered that `Obstacle(geom, velocity=(0.0, 0.0, 0.0))` is still `is_stationary=True` in PhiFlow 3.4.0 — `is_stationary` checks whether the velocity values are zero, not whether a velocity kwarg was passed. This means the structural test needs nonzero obstacle velocity to observe `is_moving=True`, which requires nonzero fluid velocity to develop forces. Resolved by seeding the initial velocity (see Deviations).
